# Kilo handoff, 2026-10-11

A self-contained briefing for a fresh Claude Code session (or a person)
picking up the Kilo project on another machine. It gathers what was learned
about the original firmware, the goals the owner set, the decisions taken,
the state of the code and the hardware, the working conventions, and what
comes next. Everything here was true on 2026-10-11 at `mega` eb287a8.

Read in this order: this file, then `docs/architecture.md` "Decisions at a
glance" (§0), §7 (phased plan) and §8 (open questions), then
`mind/README.md`, then `docs/p1-hardware-test.md` when Kilo is on the cable.

---

## 1. Who and what

- **Owner:** Joseph Burnett, the only developer and the only person who
  touches the hardware. Repo `github.com/josephburnett/OpenCat` (a fork of
  Petoi OpenCat). The integration branch is **`mega`**; `main` is still
  upstream-identical; `kilo` holds older personal mods the owner does not
  care about.
- **Kilo** is a Petoi **Nybble** (cat, 8 servos on 11 joint indices: head
  pan 0, head tilt 1, tail 2, legs 8..15 in the order LF, RF, RB, LB for
  shoulders 8..11 and knees 12..15; indices 3..7 unused). Always call it
  Kilo, never "the robot". NyBoard V1_2 (ATmega328P at 16 MHz, 32 KB flash,
  2 KB RAM; PCA9685 servo driver at 0x40, MPU6050 at 0x68 with the DMP,
  64 KB I2C EEPROM at 0x54 unused, WS2812 eyes, buzzer on D5, ultrasonic on
  the head). Kilo has the ultrasonic RGB eye module and the gyro.
- **Mind host:** a Raspberry Pi 2 Model B v1.1 (armv7l, no Wi-Fi: USB
  dongle), Raspbian 13 trixie, hostname `kilo`, user `joe`, riding on Kilo's
  back. The NyBoard reaches the Pi over a **CH343 USB serial adapter**
  (`/dev/ttyACM0` on the Pi; VID 1A86 PID 55D3). The Pi header UART path
  (`/dev/ttyAMA0`, GPIO4 to RESET) is wired on paper only and untested.
- **Dev machines so far:** the owner's laptop (WSL2 Debian 13). Development
  is moving to the owner's always-on home server (`rtb`,
  `rtb.gila-lionfish.ts.net`). The laptop had no numpy/cv2/pyserial in the
  system Python; tests ran in a throwaway venv.

### Reaching the Pi

| Route | Address | Notes |
|---|---|---|
| LAN | `ssh -o ConnectTimeout=8 -i ~/.ssh/kilo.local joe@192.168.88.32` | Works from the home network. Preferred. |
| Tailnet | `kilo.gila-lionfish.ts.net` (100.96.106.5), Tailscale SSH | Since 2026-10-11 Tailscale SSH demands a periodic browser re-check and hangs non-interactive sessions until the owner visits the link. |

The key `~/.ssh/kilo.local` must be copied to the new machine (ask the owner).

On the Pi:

```sh
export PATH="$HOME/OpenCat/.venv/bin:$HOME/.local/bin:$PATH" KILO_PORT=/dev/ttyACM0
cd ~/OpenCat && git pull && .venv/bin/pip install -e mind     # after each pull that touches mind/
```

- `~/.local/bin/arduino-cli` 1.5.1 with `arduino:avr` 1.8.8; a body build
  takes about 25 s warm, 430 MB peak RAM, no swap.
- `~/OpenCat/.venv` is a `python3 -m venv --system-site-packages` venv with
  the mind installed (`kilo` CLI) and pytest. System packages present:
  pyserial 3.5, numpy 2.2.4, PyYAML 6.0.2, picamera2. **Not** installed:
  matplotlib, OpenCV (`sudo` needs a password non-interactively, so apt
  installs need the owner at a keyboard).
- The mind daemon runs as a **systemd user service** `kilo.service`
  (lingering enabled): `systemctl --user status|stop|start kilo`, log in
  `~/kilo-logs/daemon.log`, settings in `~/.config/kilo/env`
  (`KILO_PORT=/dev/ttyACM0`, `KILO_RUN_ARGS=` empty: frame logging and
  `--behaviour` are both off). While the daemon runs, every `kilo` command
  goes through its socket `/run/user/1000/kilo/kilo.sock`; stop it before
  passive watching (`kilo monitor --passive`, `kilo posture --then-watch`).
- Gotchas: global flags go before the subcommand (`kilo -v flash`, not
  `kilo flash -v`); never run a `pkill -f` whose pattern matches your own
  remote command line (it kills the ssh shell); after any raw avrdude run,
  `stty -F /dev/ttyACM0 -hupcl` or each later port open resets Kilo (the
  mind does this itself: `clear_hupcl` and `settle_port` in
  `mind/kilo/link/transport.py`).

### Kilo's state right now

Kilo is powered down and unplugged from the Pi. The last firmware flashed
is build **975055a4**, a balance layer with the wrong pitch sign, now
superseded. The first step when Kilo is back on the cable is `kilo -v flash`
from the Pi (the mind takes the port lease from the daemon by itself).
`kilo flash --legacy` restores the original Petoi firmware
(`mind/firmware/opencat-legacy.hex`, 32016 B, md5 b3e85cc0…) at any time,
with Kilo's original calibration intact because the new firmware never
writes the legacy EEPROM layout.

## 2. What we learned about the original firmware

The legacy code is still in the repo: `OpenCat.ino` and `src/` (`OpenCat.h`,
`io.h`, `motion.h`, `skill.h`, `reaction.h`, `randomMind.h`, `taskQueue.h`,
`infrared.h`, `imu.h`, `sound.h`, `ultrasonic.h`, `InstinctNybble.h`,
`eeprom.h`, plus vendored Adafruit PWM, MPU6050 and QList libraries). It
stays until the new firmware walks (P2). The full archaeology is
`docs/architecture.md` Appendix C; the essentials:

- **Shape.** One `loop()` that polls the serial token parser, the IR remote,
  the IMU (every third servo write), the ultrasonic reactions, a random
  "mind", and steps the current skill's frames with `delay()`. There is no
  fixed-rate motor loop; timing depends on what else runs.
- **Protocol.** Single-character tokens at 115200 baud (`k<skill>`, `m`/`i`
  joint moves, `c` calibrate, `b` beep, `v` print ypr, `j` print joints,
  `d` rest, …). Dropped entirely in the new design.
- **Skills.** Postures and gaits are int8 tables in `InstinctNybble.h`
  (a header with frame count, expected roll/pitch, angle ratio and loop
  bounds, then 16 joint angles per frame). "Instinct" skills live in
  PROGMEM or the I2C EEPROM, "newbility" skills in on-chip EEPROM, written
  by a separate setup sketch. Gaits are precomputed frame tables, not
  generated. `Skill::mirror()` swaps the left/right columns.
- **Calibration and servo transfer.** The setup sketch stored per-joint
  calibrated zero positions, counts-per-degree factors and a base offset in
  EEPROM 0..282, with integer-division quirks (neutral ≈1590 counts, 11
  counts per degree). Kilo's own values were dumped and committed as
  `docs/kilo-eeprom-legacy.md`; the new firmware **imports** them instead
  of recomputing, and reproduces the legacy pulse within ±1 count (a host
  test replays Kilo's exact dump).
- **Balance** (`motion.h` `adjust()`): proportional only, in joint space,
  with per-joint roll/pitch gains, ±5° per-update slew, 5°/3° dead bands.
  The roll term was effectively wrong-signed (only a 20% asymmetry). The new
  balance layer keeps the legacy gain table so the feel carries over, adds a
  derivative term and runs at a fixed 50 Hz.
- **Attitude convention, measured on Kilo 2026-10-10:** nose DOWN is
  +pitch, RIGHT side up is +roll (the legacy `ypr`). Earlier docs had both
  backwards; everything is now consistent with the measurement. The
  constants `LEGACY_PITCH_SIGN=+1` and `LEGACY_ROLL_SIGN=-1` in
  `body/src/core/balance.h` are the place to flip if a leg answers a tilt
  the wrong way in the P1 hardware test.
- **Fall recovery** is the `rc` skill, mirrored by the roll sign; kept as a
  body reflex in the new firmware (PROGMEM frames).
- **Why it had to go.** Flash. Gyro + ultrasonic + IR did not fit (36.6 KB
  for 32.25 KB). Two cleanup rounds on 2026-10-09/10 (on `mega`, the
  commits before the new design) got the stock design to 32016 B with all
  three on, byte-identical hex verification, and were flashed and verified
  on Kilo. That bought 240 B of headroom and showed the architecture
  itself (blocking loops, token parsing, EEPROM skills, float maths,
  HardwareSerial/Wire/Print) was the limit. Found on the way: ultrasonic
  reactions bypass the skill player and fight the gyro head levelling.
- **Pi integration findings:** `docs/raspberry-pi.md` (mount, 5 V 3 A buck
  on the NyBoard for the Pi, the Arduino/Pi I2C switch must stay on
  Arduino, header pinout derived from docs and flagged unverified, one
  UART shared with the USB socket).

## 3. Goals and decisions (the owner's)

Recorded in `docs/architecture.md` §1 and "Decisions at a glance"; the
memory of how they were made:

- **The Pi is always onboard.** "I'm committed to having the Pi always
  onboard. I want to optimize this setup for capability. Let's build this
  right." No Petoi compatibility (token protocol, app, serialMaster, setup
  sketch) is kept. Nybble only, never Bittle, never 12 DoF.
- **Purpose:** (1) a companion with personality that explores, reacts to
  people and obstacles, rests when tired, expresses mood with head, tail,
  eyes, tricks and sounds, with the personality on the Pi; (2) a platform
  for learning control: fixed-rate loop, explicit owner model, parametric
  gait with real IK, tunable balance, everything live-tunable and loggable
  at 50 Hz; (3) safety on the body within one tick, no Pi involved;
  (4) verifiable by construction: firmware logic is plain C++ that runs on
  the desktop, one protocol spec with cross-language vectors, size and
  symbols checked on every build.
- **Split:** BODY = new NyBoard firmware in `body/` (50 Hz tick,
  arbitration REFLEX > TRICK > GAIT > IDLE per joint with a 200 ms
  crossfade, head and balance layers, limits and slew, reflexes, two-stage
  link watchdog: stop at 0.5 s, REST at 1.5 s, LIMP 10 s later). MIND =
  Python on the Pi in `mind/` (daemon, behaviour tree under a utility
  selector over drives, perception, trick library, logging, flashing).
  PROTOCOL = `protocol/spec.toml` is the authority; COBS + CRC-16 at 250000
  baud; goals unacked and refreshed at 5 Hz with an epoch byte so stale
  goals are refused after a reflex or reboot; commands acked and
  de-duplicated; queries answered by their data reply.
- **Owner decisions along the way:** drop the IR remote; keep the buzzer,
  Pi-driven; first tricks are the basics (sit, rest, stand, stretch,
  balance) plus the social ones (hi, wash face, check around, sniff,
  scratch, pee, push-up, butt-up), athletic ones (backflip, roll, jump) not
  ported; phase order talk/stand (P0), tricks (P1, balance first), walking
  (P2); flash ceilings P0 20 KB, P1 24 KB (raised 2026-10-11 together with
  adopting `-mcall-prologues -Wl,--relax`), P2 30 KB (raised from 24 KB
  later on 2026-10-11 after `docs/firmware-size-report.md`); the daemon's
  `--behaviour` flag stays **off** on the Pi until the P1 hardware tests
  pass, and is enabled only when the owner says so.
- **Later phases:** P3 personality v1 (ultrasonic + IMU), P4 camera (none
  chosen yet), P5 remove the DMP for an integer complementary filter
  (≈3.5 KB back).

**P0 (protocol + skeleton body): done and passed on Kilo 2026-10-10.** Log:
`docs/p0-hardware-test-results.md`. Flash from the Pi, legacy calibration
import, postures, watchdog timeline (stop 0.5 s, REST 1.5 s, LIMP 12.5 s),
power cycle, params, rollback to legacy, all verified. Findings fixed on the
way: the tail joint's direction is +1 on Kilo (upstream had flipped it for
Bittle); the USB adapter must win over the header UART as the default port;
avrdude re-enables HUPCL so every later open reset Kilo (the mind now clears
it and settles the port after flashing; one residual post-flash double reset
was seen and the settle fix is unverified on hardware).

**P1 (motor loop, tricks, balance, reflexes): complete on the host, not yet
run on Kilo.**
- Joint-space balance layer with the legacy gain table, gating, live
  tuning (`kilo balance on|off --kp --kd --deadband --clamp --posture --for`),
  attitude A/B against the legacy float path within 0.04° on the host.
- Trick player: 24 keyframes in RAM, uploaded by the Pi with CRC and a
  cache check, speed and mirror on the body, 13 library tricks converted
  from `InstinctNybble.h` into `mind/kilo/tricks/library/*.json`
  (`kilo trick list|show|upload|play|stop`). The legacy frame timing is an
  estimate (5.5 ms per step) to be calibrated against video.
- Fall reflex (6 consecutive samples over 75°, then `rc`, mirrored by roll
  sign, up to 3 tries) and the head layer (`kilo look PAN TILT`).
- Boot epoch from a `.noinit` reset counter so a rebooted body refuses the
  mind's stale goals.
- Not in the new firmware yet: eyes, buzzer, PCINT ultrasonic (about 2.4 KB
  of room left); `kilo cal imu`; a keyframe editor (needs a joint-jog
  message); the GPIO4 reset path.

**Mind:** daemon `kilo run` (JSON-lines Unix socket, port lease for
flashing, hot-plug retry, REST/LIMP idle latch, `kilo daemon status|stop`),
behaviour engine (`mind/kilo/behaviour/`, `personality.yaml`, drives,
utility selector, runnable standalone with `python -m kilo.behaviour`),
perception (`mind/kilo/perception/`: ultrasonic near/approaching/clear, IMU
tilted/picked_up/tap/pet/startle), logs (`.kilolog` writer, `kilo log
summary|replay|plot`), `kilo monitor --percepts --rate --json`, a virtual
body on a pty for tests (`python -m kilo.vbody`). Two independent reviews
were applied (17 findings each time, none critical); one flaky test was
root-caused to a watchdog race and fixed.

## 6. How the owner wants to work

These came from explicit corrections during the sessions. They matter more
than any default.

- **Ask before touching machines.** Say what you intend to do on the Pi,
  rtb or anything other than the local shell, and get a yes first. The
  owner wants the work done, but asked for the ask ("I do want you to do
  this. But I want you to ask first next time."). Routine read-only checks
  locally are fine. Standing grants are per occasion, not permanent.
- **Ask before environment and tooling choices** (toolchains, where things
  install, how hardware is reached). Exception: Python tooling is
  delegated: per-repo venv with `--system-site-packages`, pytest in it.
- **Never put the owner on a timer.** Steps that need hands on Kilo must be
  open-ended: open-ended recordings, commands that wait, "answer when
  done". "Don't assume I'm reading your messages and acting right away."
  "I'm not on your schedule."
- **Decisions go through AskUserQuestion**, followed by a short high-level
  status report.
- **Subagents:** use Opus subagents for the heavy lifting to preserve the
  main context; the main session coordinates and verifies their work. Each
  editing agent works in its own git worktree on a branch off `mega`
  (worktrees created by the Agent tool start at `main`, so the agent must
  `git merge --ff-only mega` first), verifies on its branch, then the main
  session merges into `mega` and re-runs all four suites on the merged tree.
  Work that needs Kilo stays serial: there is one Kilo.
- **Push `mega` after every commit or merge**, no asking, never force-push.
  "No one is depending on this. There will be no code review."
- Commit messages carry a `Co-Authored-By: Claude …` trailer.
- Write hardware procedures as documents in `docs/` the owner can follow
  alone, with expected observations per step, and log results in a
  `*-results.md` next to them.

## 7. Environment setup, as it was done here

Reproduce this on the home server (the dev host) and keep the Pi as it is.
Nothing below needs root on the dev host beyond apt.

### 7a. The dev host (what the laptop has, and the server needs)

Versions in use on the laptop, all from Debian 13 apt unless noted:

| Tool | Version | Purpose |
|---|---|---|
| `build-essential`, `g++` (+ `libasan8`) | gcc 14.2 | body host tests with `-fsanitize=address,undefined` |
| `python3`, `python3-venv` | 3.13 (3.11+ is enough) | mind |
| `git`, `jq`, `tmux` | any | |
| `gh` | any | GitHub CLI (used for pushes/PR-free work only) |
| `arduino-cli` | 1.5.1, core `arduino:avr` 1.8.8 | build the body (optional on the dev host: the Pi can build and flash) |

Steps:

```sh
sudo apt install build-essential g++ git jq tmux python3 python3-venv
# arduino-cli into ~/.local/bin (no root), then the AVR core:
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | BINDIR=~/.local/bin sh
~/.local/bin/arduino-cli core update-index && ~/.local/bin/arduino-cli core install arduino:avr
# the repo and the mind venv (the same recipe as the Pi):
git clone git@github.com:josephburnett/OpenCat.git ~/OpenCat && cd ~/OpenCat && git checkout mega
python3 -m venv --system-site-packages .venv
.venv/bin/pip install -e mind pytest           # add numpy for the one skipped test
# verify:
body/tools/host_tests.sh && body/tools/size_check.sh && protocol/test.sh && (cd mind && ../.venv/bin/python -m pytest -q)
```

`size_check.sh` needs arduino-cli; the other three do not. `protocol/test.sh`
finds pytest through the venv on PATH (`export PATH="$HOME/OpenCat/.venv/bin:$PATH"`).
`.venv/` is gitignored.

Claude Code specifics that shaped the work: permission mode `auto`, model
Fable, subagents mostly Opus, editing agents in worktrees that the Agent tool
creates under `.claude/worktrees/` (gitignored). No hooks, no MCP servers, no
project `CLAUDE.md`; this document and the memory conventions in §6 are the
project instructions. The `gopls-lsp` plugin that was enabled is not needed.

USB passthrough (usbipd-win into WSL2) was the laptop's way to reach the
CH343 adapter before the Pi existed; it is irrelevant now that the adapter
lives in the Pi.

there, or copy the laptop's `~/.ssh/kilo.local` private key to the server
(the owner's choice on 2026-10-11).

### 7c. Day-to-day loop from the dev host

1. Edit and test on the dev host (the four suites above).
2. Commit on `mega`, push.
3. On the Pi: `cd ~/OpenCat && git pull && .venv/bin/pip install -e mind`
   (the editable install makes a plain pull enough unless `pyproject.toml`
   changed), then `systemctl --user restart kilo` if the daemon code changed.
4. Firmware: `kilo -v flash` on the Pi (builds there, about 25 s). Always ask
   the owner before anything that moves Kilo.
